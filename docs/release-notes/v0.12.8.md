**A document can now answer for itself.** Ask "what are the chapters?", "who are
the characters?", "what are all the priorities?" and the answer is not a
sentence sitting in one passage — it is the whole document. Retrieval hands the
model six passages of about 350 words, ranked by word overlap, and a question
like "what terms does the glossary define?" shares no vocabulary with the terms
it is asking for.

Measured on a 22-chunk glossary before this release: the model was shown **one
of the twenty-two passages and 26 of the 82 terms**. Raising the budget
eight-fold reaches 89%, not 100% — so the obvious fix was measured and does not
work.

So the document's own structure answers what it can, with no model at all:

| the question | where the answer comes from |
|---|---|
| what are the chapters? | the headings |
| who are the persons in the play? | the list under the heading that says so |
| what terms does the glossary define? | the paragraphs that open with one |
| what is the second chapter? | an ordinal into the same list |
| what happens in the fourth act? | *refused* — the play has three, and it says so |

| seven such questions, through the real cascade with no model | result |
|---|---:|
| accuracy · false answers · determinism · cost | **100% · 0 · 100% · $0** |

That runs in CI on every push. An ordinal past the end refuses **with the
count** — "Earnest has 3 acts; there is no fourth one" — because the
alternative is a model inventing a fourth act.

Two votes are required before any of this happens: the question's shape, and
retrieval concentrating on a single document. Either alone changes nothing, and
every question in the four older evaluation sets takes the path it always did.

**A summary now reads the named section in order** rather than six ranked
passages — as far as the model's context window allows, and the answer says so
when the document is longer than that. What a model makes of that is **not yet
measured**; this machine answers one question every two to three minutes and the
comparison was still running. The structure half above needs no model, and is
the half claimed here.

**The "asked and not answered" report no longer shows gaps you have closed.**
Every row is re-checked against the tiers that cost nothing, and rows that would
be answered today are separated from rows that are still open. Measured on a
real install: four of sixteen rows had been fixed a week earlier and were still
listed, because a row only cleared when somebody asked the question again — and
nobody re-asks a question that failed them once.

**A typo costs less than expected, so nothing was built for it.** Two of those
sixteen questions were misspelled, which looked like a gap worth closing. 40
cases across four corpora, 160 question-and-typo pairs: **156 still retrieve the
document they need, 97.5%**. A question carries several content words and the
index finds the document on the others. The harness is committed so the decision
can be re-taken when the number moves.

Also here: a set of sixteen questions that state a figure and need it compared
against a threshold — "we want to buy a EUR 40,000 platform, do we need
quotes?" — which two earlier evaluations found the system refuses. The set is
written and its retrieval pre-flight passes; no result is claimed yet.

Nothing in this release changes what a fact question does.
