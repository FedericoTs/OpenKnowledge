**A question that states a figure now gets an answer.** "We want to buy a EUR
40,000 platform — do we need quotes?" The threshold is in the documents. The
answer was *"I don't know — that isn't covered by the documents I have."*

Two earlier evaluations had found this independently and neither was built to
measure it, so a sixteen-case set was written for it. The prediction recorded
before the run blamed the prompt. It was wrong.

**The model was answering. The gate was throwing the answer away.** Every
answer is checked against its sources, and any figure that appears in no source
is treated as invented — the rule that stops a model making numbers up. The
asker's own figure appears in no source *by definition*. So "EUR 40,000 is
above EUR 25,000" was an invention, and the correct answer was discarded.

Measured with no model at all, by gating answers written by hand:

| an answer that… | gate |
|---|---:|
| avoids the asker's figure | 6 of 6 pass |
| states the asker's figure | **6 of 6 rejected** |

The question's figures now count as evidence, as the passage headers already
did. Then that was attacked: *"is the limit EUR 87,500?"* — and *"yes, the limit
is EUR 87,500"* went from rejected to accepted, a leading question writing a
number into policy. So the asker's figure is admitted only in an answer that
**also** states a figure from the sources. Comparing, not parroting.

| sixteen apply-the-rule questions, local model, BM25 | before | after |
|---|---:|---:|
| accuracy | 28.6% | **57.1%** |
| refused | 9 | **4** |
| false answers | 0 | **0** |

Four cases moved from refusal to a correct answer. The two that sit at *exactly*
EUR 25,000 still get the band wrong; that is the next piece of work, and it is
not fixed here.

**And a false answer this project shipped this afternoon is fixed.** Before
changing the gate, all four refusal sets were re-run as a guard — 32 questions
whose only correct answer is "I don't know". One came back answered, and it was
not this change:

> **Does the parental leave policy cover adoption?**
> *Parental Leave Policy has 4 sections: 1. Entitlement 2. Notice 3. Taking
> leave 4. Return to work*

Adoption appears nowhere in that corpus. That is a non-answer in the shape of an
answer, about a legal entitlement, and the case's own note had anticipated it:
*"a helpful-sounding yes here is a fabrication."* It came from the
whole-document feature released in **v0.12.8** — the structure path recognised
"cover" beside a document title and answered with the section list. It bypasses
the gate entirely, so the fix above could never have caught it.

The rule it needed already existed one tier away: a question qualifies only when
removing its vocabulary leaves nothing behind, which is why *"which documents
mention adoption"* was already refused. The coverage branch now applies it too,
forgiving the document's own name.

| the guard, after both fixes | false answers |
|---|---:|
| 32 refusal questions across four sets | **0** |

The whole-document set is unchanged at 100%.

Two failures in that set are the exam's fault, not the system's, and are
recorded as such: one demands a citation to a document that states the same
bands as the one cited, and one is refused as contested because the corpus
genuinely disagrees with itself.
